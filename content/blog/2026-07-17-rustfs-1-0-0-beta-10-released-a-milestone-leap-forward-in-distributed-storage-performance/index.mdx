今天，我们很高兴地宣布 **RustFS 1\.0\.0\-beta\.10** 正式发布。

这是 RustFS 的一个里程碑版本。与之前版本相比，**1\.0\.0\-beta\.10 在性能和稳定性方面都有显著提升**。在与 MinIO 的基准测试中，RustFS 的 **PUT 请求性能已全面领先 MinIO**，GET 请求的性能差距也在持续缩小。

## 架构与质量方面的主要改进

除了性能提升，`1.0.0-beta.10` 还在整个软件栈中引入多项严格的生产级增强：

- **优化核心存储路径：** 精简数据路径、降低锁延迟、加强 I/O 可观测性，并提升整体吞吐稳定性。
- **S3 兼容与复制：** 修复大量边界场景兼容问题、存储桶复制死锁和生命周期收敛延迟。
- **加强默认安全：** 修复多个 GHSA 级授权漏洞，并移除存在风险的默认配置回退。
- **解耦模块化架构：** 抽取核心存储、配置与执行运行时契约，系统性降低历史代码与 `ECStore` 的耦合。
- **企业级 CI/CD 门禁：** 升级发布流水线，加入自动生成软件物料清单（SBOM）、SLSA 来源验证、严格依赖版本锁定和多层端到端（E2E）回归测试。

## 重要迁移与升级说明

为遵循现代安全最佳实践并避免默认部署遭到未授权访问，**我们已弃用硬编码的默认回退凭据**（`rustfsadmin`）。

### 安全增强

- 用户现在必须在启动服务器前**显式指定** `RUSTFS_ACCESS_KEY` 和 `RUSTFS_SECRET_KEY`。
- 如果仍保留默认占位值，运行时将拒绝启动服务器。

### 现有集群需要执行的操作

- 如果当前 `RUSTFS_SECRET_KEY` 仍为 `rustfsadmin`，必须新增环境变量 `RUSTFS_RPC_SECRET`。
- *注意：* `RUSTFS_RPC_SECRET` 的值**必须不同于** `RUSTFS_SECRET_KEY`。
- 如果已经使用自定义 Access Key 和 Secret Key，则无需额外操作。

## 生态更新

企业级对象存储系统同样需要可靠的开发者工具链。随服务器版本一起发布的，还有命令行工具和 Kubernetes Operator 的重要更新。

### `rc` CLI（v0\.1\.27）—— 原生命令行工具

RustFS 专用命令行客户端 `rc`（类似 MinIO 的 `mc`）已增强多流上传逻辑，并提升本地到远程目录的同步速度。

- **快速配置与验证：**

```Plain Text
# 设置集群连接别名
$ rc alias set rustfs http://<your-ip>:9000 rustfstest rustfstest
✓ Alias 'rustfs' configured successfully.

# 创建并列出存储桶
$ rc mb rustfs/benchmark-bucket
✓ Bucket 'rustfs/benchmark-bucket' created successfully.

$ rc ls rustfs
[2026-07-16 14:30:01]         0B benchmark-bucket/

# 以流式方式上传本地文件
$ echo "RustFS performance milestone" > test-object.txt
$ rc cp test-object.txt rustfs/benchmark-bucket
test-object.txt -> rustfs/benchmark-bucket/test-object.txt (29 B)
```

详细用法请查看 [RustFS CLI GitHub 仓库](https://github.com/rustfs/cli)。

### RustFS Operator（v0\.0\.5）—— 原生 Kubernetes 编排

云原生 **RustFS Operator** 已实现基础设施全自动化，并新增原生**多租户管理**与**动态存储池扩容**能力。

- 第 1 步：添加官方 Helm 仓库

官方 Chart 已发布至 [Artifact Hub](https://artifacthub.io/packages/helm/operator/rustfs-operator)。

```Plain Text
$ helm repo add operator https://operator.rustfs.com
```

- 第 2 步：安装 Operator 与管理控制台

```Plain Text
helm install operator operator/rustfs-operator --version 0.0.5
```

部署完成后，可以看到 Operator 控制器和管理控制台 Pod 正常运行：

```Plain Text
kubectl -n rustfs-system get pods
NAME                                                READY   STATUS    RESTARTS   AGE
operator-rustfs-operator-978454bf4-zgdp9            1/1     Running   0          3d14h
operator-rustfs-operator-console-7cfbf88c84-m7ct2   1/1     Running   0          3d14h
```

- 第 3 步：以声明式方式部署多租户集群

应用以下自定义资源（CRD），即可自动创建一个包含 4 个节点、16 块存储磁盘的高可靠租户集群：

```YAML
kubectl apply -f - <<EOF
apiVersion: rustfs.com/v1alpha1
kind: Tenant
metadata:
  name: svt-minimal
  namespace: tenant-svt
spec:
  image: rustfs/rustfs:latest
  pools:
    - name: dev-pool
      servers: 4
      persistence:
        volumesPerServer: 4
EOF
```

检查租户信息：

```SQL
# kubectl -n tenant-svt get tenant
NAME          STATE   AGE
svt-minimal   Ready   3d14h

# kubectl -n tenant-svt get pods
NAME                     READY   STATUS    RESTARTS        AGE
svt-minimal-dev-pool-0   1/1     Running   0               3d14h
svt-minimal-dev-pool-1   1/1     Running   0               3d14h
svt-minimal-dev-pool-2   1/1     Running   0               3d14h
svt-minimal-dev-pool-3   1/1     Running   0               3d14h
```

完整 Helm 参数映射与高级配置请查看 [RustFS Kubernetes Operator GitHub 仓库](https://github.com/rustfs/operator)。
